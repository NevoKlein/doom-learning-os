# Codex Execution Plan

## A — Audit
Read the complete repository. Report architecture, content structure, UX, data safety, resource quality, broken/outdated links, technical debt and conflicts with the current character-first project strategy.

## B — Stabilize sources of truth
Keep curriculum, resources, strategy, decisions, research and changelog understandable and version-controlled. Never destroy saved progress.

## C — Learning OS
Make the active milestone, exact next action, prerequisites, learn/build/test state, progress, notes and required resources immediately visible.

## D — Architecture
Migrate from the static page to modular/app architecture only when justified. Preserve behavior during refactors.

## E — Cloud sync
When needed, add authentication, database-backed progress, notes/session history and safe localStorage migration. Keep backup/export.

## F — Sharing
When justified, add shared project workspaces, roles and public read-only views without exposing private state.

## G — Production quality
Add tests, migrations, error handling, accessibility, performance checks, security checks, previews, environment management and documentation.

## H — Continuous improvement
Keep researching resources, replacing obsolete material, improving curriculum order, refining UX and recording decisions.

## Definition of done
A substantial change is complete only when the app works, data is preserved, tests pass, current resources are verified, deployment behavior is checked and documentation reflects the new state.
